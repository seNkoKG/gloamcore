# GitHub update hosting

GloamCore uses the stable
`seNkoKG/gloamcore` GitHub Releases channel. Earlier builds have updates
disabled and must install 2.2.8 manually once.

## Runtime behavior

The packaged configuration is intentionally public and credential-free:

```json
{
  "enabled": true,
  "provider": "github",
  "owner": "seNkoKG",
  "repo": "gloamcore"
}
```

The same GitHub provider coordinates appear in `package.json` under
`build.publish`. The updater does not accept a token, private-repository flag,
or arbitrary provider field from the shipped configuration.

When **Check automatically** is enabled, the installed app checks shortly after
launch and every four hours while it remains open. Only stable releases are
considered. A newer installer downloads automatically, but installation waits
for the user to click **Restart & install**. **Check now** runs the same check on
demand.

The NSIS-installed build is the supported in-app update path. Portable users
should download and replace the portable executable manually.

## Required assets for every stable release

Publish a non-draft, non-prerelease GitHub Release tagged `vX.Y.Z` with:

- `latest.yml` generated by `electron-builder`;
- `GloamCore-Setup-X.Y.Z-x64.exe`;
- `GloamCore-Setup-X.Y.Z-x64.exe.blockmap`;
- `GloamCore-Portable-X.Y.Z-x64.exe`;
- `GloamCore-Setup-x64.exe`, a byte-identical alias of the versioned setup
  executable for the permanent README download link;
- `SHA256SUMS.txt` covering the human-downloadable release files.

`latest.yml` is the machine-readable update contract. Its version, filename,
size, and SHA-512 must match the uploaded versioned NSIS installer. The stable
alias is for people and is not substituted into updater metadata.

## Release procedure

1. Choose a higher semantic version. Update `package.json`, the changelog, and
   any versioned release documentation together.
2. Run the complete test, build, native smoke, and artifact-verification suite.
3. Build from the reviewed clean source commit with `pnpm dist`.
4. Verify the generated installer, blockmap, portable executable, `latest.yml`,
   and checksums before uploading anything.
5. Create tag `vX.Y.Z` from that exact source commit and publish one stable
   GitHub Release containing the required assets above.
6. Verify that the permanent installer URL resolves:
   `https://github.com/seNkoKG/gloamcore/releases/latest/download/GloamCore-Setup-x64.exe`.
7. From the previous installed stable version, use **Check now**, allow the
   download to finish, click **Restart & install**, and verify the new version
   plus preserved user data.

Do not replace binaries or metadata on an already published tag. If a release
has a defect, publish a corrected higher version so installed clients receive a
monotonic, auditable update.

## Trust and signing boundary

`electron-updater` verifies the downloaded file against the SHA-512 recorded in
the release metadata. That detects a damaged or mismatched asset, but it does
not replace Authenticode publisher verification. Current public binaries are
unsigned, so GitHub account security, protected release credentials, reviewed
automation, and immutable published artifacts are part of the update trust
boundary.

Protect the GitHub account with strong multi-factor authentication, give release
workflows only the permissions they need, never expose a release token to the
app, and keep signing material out of the repository. If Authenticode signing is
added later, keep a stable publisher identity and test upgrade verification
before changing the public channel.

For local development QA only, `GLOAMCORE_UPDATE_URL` can select an HTTPS
generic feed when the process explicitly allows environment overrides.
Packaged builds ignore that override.
