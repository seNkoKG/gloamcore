# GloamCore 3.3.0

GloamCore 3.3.0 adds a durable, privacy-bounded Mapping Journal inside Player
Toolkit on Windows. Android, iOS, and the browser explain the desktop boundary
instead of pretending they can observe a local PoE client log.

## Verified map sessions

- A session requires three matching PoE 1 `Client.txt` facts from the same
  client process: the current client-safe instance ID, an internal
  `MapWorlds…` generation record, and the displayed area-entry record.
- The client-safe instance ID, internal area ID, and seed identify one map
  instance. Re-entering through another portal increments its entry count.
- Observed in-area time begins at the entry record and stops at the next exact
  area-generation boundary. Rotation, replacement, restart, or disabled
  observation cannot silently inflate time; interrupted sessions are marked
  incomplete.
- Death counting is opt-in and accepts only exact, case-sensitive system lines
  for the configured active character. Party and unrelated names are ignored.

## Local journal and league updates

- Search sessions, review observed facts, add bounded notes and tags, remove an
  individual session, deliberately clear the journal, or export CSV to a
  user-selected file.
- Only sanitized facts and annotations persist. Raw log lines, chat, network
  addresses, other character names, and instance seeds are not stored.
- Exact current map artwork is resolved from the selected league's validated
  poe.ninja mirror, with the current official Atlas map sprite as fallback.
  Session classification itself depends on `MapWorlds`, not a frozen map-name
  list, so new league Atlas rotations do not require guessed name updates.
- GloamCore does not infer loot, profit, completion, boss kills, portal counts,
  or hidden game state.

League Navigator, Atlas Command Center, Build Lab, Craft of Exile, and the
bounded Ctrl+D seller snapshot remain intact. This release does not restore the
retired full official-trade-listings subsystem.
